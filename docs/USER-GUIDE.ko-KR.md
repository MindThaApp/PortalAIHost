# Portal AI Host: 사용자 가이드

Portal AI Host는 내 PC에서 AI 모델을 실행하고 이를 Portal 앱과 함께 사용하게 해 줍니다. 질문과 파일은 내 기기 안에 머뭅니다. 이 가이드는 앱의 모든 부분, 각 설정의 역할, 문제가 생겼을 때 해야 할 일을 설명합니다.

사진이 들어갈 자리는 `[스크린샷: ...]`으로 표시했습니다.

## 1. 빠른 시작

1. Microsoft Store에서 Portal AI Host를 설치하고 엽니다.
2. 환영 창에서 PC(메모리, 그래픽 카드, 여유 디스크 공간)를 확인하고 모델 하나를 추천합니다. **추천 설정으로 시작**을 고르거나, **다운로드**를 눌러 직접 모델을 고를 수 있습니다. **나중에 선택**을 누르면 건너뜁니다.
3. 시계 근처의 트레이 아이콘을 찾아보세요. Portal AI Host는 그곳에서 조용히 대기합니다. 클릭하면 간단한 상태를 볼 수 있습니다.
4. **체험해 보기**를 열고 짧은 질문을 해서 모델이 동작하는지 확인하세요.
5. Portal 앱이 처음으로 AI를 사용하려고 하면, 허용할지 거부할지 묻는 창이 뜹니다.

[스크린샷: 추천 모델이 표시된 환영 창]

대신 노트북에서 집 PC의 AI를 쓰고 싶다면, 환영 창에서 **내 집 PC 사용**을 선택하세요. 12절을 참고하세요.

**무료인가요, 유료인가요?** Portal AI Host는 무료입니다. 이 가이드의 어떤 기능도 계정, 로그인, 구매가 필요하지 않습니다.

## 2. 시스템 요구 사항, 설치, 업데이트, 제거

### 요구 사항

| | 최소 | 권장 |
|---|---|---|
| Windows | Windows 11(21H2, 빌드 22000) 이상, x64 또는 Arm64 | 동일 |
| 메모리 | 8GB | 16GB 이상 (대형 모델은 32GB 이상) |
| 그래픽 | 없음 (모델이 프로세서에서 실행되며 느립니다) | 비디오 메모리 8GB 이상의 Vulkan 지원 그래픽 카드 (AMD, NVIDIA 또는 Intel) |
| 여유 디스크 공간 | 5GB | 25GB |

모델은 각각 2~20GB입니다. Arm64 PC는 프로세서에서 모델을 실행합니다. 인터넷 연결은 모델을 내려받을 때와 릴레이를 사용할 때만 필요합니다. 모델이 PC에 있으면 오프라인에서도 동작합니다.

### 설치

Microsoft Store에서 설치합니다. 그 밖에 필요한 것은 없습니다. Python, 명령줄, 다른 소프트웨어가 필요 없습니다. AI 엔진은 앱의 일부로 포함되어 있습니다.

### Windows 시작 시 자동 실행

**설정 > 일반 > Windows 시작 시 자동 실행** (기본값: 꺼짐. 단, 환영 창의 "추천 설정으로 시작"을 누르면 켜집니다). 켜 두면 로그인 후 Portal AI Host가 트레이에서 대기하므로, 앱이 바로 AI를 사용할 수 있습니다.
- 스위치에 "설치된 앱에서만 사용 가능"이라고 나오면 개발용 복사본을 실행 중인 것입니다.
- 작업 관리자(시작 앱)에서 껐다면 거기서 다시 켜세요.
- 조직에서 설정한 경우 스위치가 잠겨 있습니다.

### 업데이트

Store가 앱을 업데이트합니다. 업데이트 후 **새로운 기능**이 한 번 열립니다. 앱 메뉴에서 언제든 다시 열 수 있습니다.
모델은 업데이트 후에도 그대로 유지됩니다.

### 제거

**Windows 설정 > 앱**에서 앱을 제거합니다. 기본 폴더의 모델은 앱 자체 데이터 안에 저장되어 있어 함께 삭제됩니다. 직접 선택한 사용자 지정 모델 폴더는 건드리지 않습니다. 남기고 싶은 것이 있다면 제거하기 전에 15절을 확인하세요.

## 3. 화면 둘러보기

왼쪽에 다섯 개의 페이지가 있습니다.

| 페이지 | 용도 | 단축키 |
|---|---|---|
| 홈 | 상태, 사용 중인 모델, 메모리 사용량, 지금 AI를 사용 중인 앱 | Ctrl+1 |
| 모델 | 모델 다운로드, 사용, 삭제 | Ctrl+2 |
| 기기와 앱 | Portal 앱 허용 또는 제거, 일시 중지, 우선순위 설정 | Ctrl+3 |
| 체험해 보기 | 모델에 짧은 질문 하나 하기 | Ctrl+4 |
| 설정 | 설정할 수 있는 모든 항목 | Ctrl+, |

여섯 번째 페이지인 **이 PC의 기기**에는 이 PC와 페어링된 노트북과 휴대폰이 표시됩니다(10절 참고). 앱 메뉴에는 설정, 키보드 단축키, 새로운 기능, 정보가 있습니다.

**홈**에는 AI 상태가 준비됨, 답변 중, 모델 준비 중, 대기 중(앱이 요청하면 모델이 깨어남), 또는 아직 모델 없음으로 표시됩니다. **지금 상황**에는 답변을 받고 있는 앱과 대략 초당 몇 단어가 생성되는지 표시됩니다. 모델이 사용 중인 메모리와 그래픽 메모리 양도 보여 주며, **지금 불러오기** / **지금 해제** 버튼이 있습니다. **오늘**에는 앱별 요청 횟수가 집계됩니다. 상태 카드에는 "모두 정상" 또는 확인이 필요한 항목이 나열되며, 각 항목에는 모델 불러오기, 엔진 다시 시작, 파일 확인, 성능 설정 열기 같은 원클릭 해결 버튼이 있습니다.

[스크린샷: 앱이 모델을 사용하는 동안의 홈 페이지]

트레이 아이콘을 클릭하면 작은 팝업이 열립니다. 모델, 메모리, 마지막 요청과 대기열이 보이고, **앱 열기**와 **모델 해제** 버튼이 있습니다.

[스크린샷: 트레이 팝업]

호스트 프로그램이 실행 중이 아니면 홈에 **Portal AI Host 시작** 버튼이 나타납니다. 예기치 않게 여러 번 종료되었다면 **안전 모드** 막대가 표시되며, 앱이 보수적인 설정으로 시작되었음을 알려 줍니다. Portal 앱은 계속 작동합니다. 계속 발생하면 PC를 다시 시작하세요.

## 4. 모델

모델은 실제 작업을 수행하는 AI입니다. **모델**(Ctrl+2)에서는 가지고 있는 모델과 추가할 수 있는 모델을 볼 수 있습니다.

### 추천 모델

처음 실행할 때와 홈 화면에서는 메모리, 그래픽 메모리, 여유 디스크 공간을 바탕으로 "이 PC에 가장 적합한 모델"을 이유와 함께 추천합니다. 더 나은 모델을 쓸 수 있게 되면 **더 나은 모델을 사용할 수 있습니다** 막대가 표시됩니다. 새 모델이 준비될 때까지 현재 모델은 계속 사용할 수 있고, 이전 모델을 언제 제거할지는 직접 선택합니다.

### 모델 다운로드

1. **모델**을 열고 **추가할 수 있는 모델**에서 모델을 고릅니다.
2. **다운로드**를 누릅니다. 진행률과 남은 시간이 막대에 표시됩니다.
3. 언제든지 **일시 중지**와 **재개**를 할 수 있습니다. **중지**를 누르면(확인 후) 이미 받은 부분은 버려집니다.
4. 호스트는 다운로드한 파일을 사용하기 전에 검사합니다.
5. 완료되면 **이 모델 사용**을 누릅니다.

다운로드는 재시작 후에도 이어서 받을 수 있으며, 파일 단위로 검사됩니다. 다운로드에는 충분한 여유 디스크 공간이 필요합니다. 공간이 부족하면 페이지에 부족한 양이 표시되고 **설정에서 폴더 변경** 옵션이 제공됩니다. 다운로드 중에는 PC가 깨어 있도록 유지됩니다(설정 > 성능, 기본값: 켜짐).

[스크린샷: 다운로드가 진행 중인 모델 페이지]

"이 PC에는 너무 클 수 있음"으로 표시된 모델도 다운로드는 가능하지만, 느리게 동작하거나 제대로 실행되지 않을 수 있습니다.

### 상세 정보, 파일 확인, 다시 다운로드, 제거

- **상세 정보**에서는 모델이 무엇에 좋은지, 주의할 점, 필요한 메모리, 라이선스, 마지막 사용 시점, 사용 중인 공간을 볼 수 있습니다.
- **파일 확인**은 디스크의 모델을 다시 검사합니다. 아무것도 삭제하지 않습니다. 손상된 모델은 **손상됨**으로 표시됩니다.
- **다시 다운로드**(손상된 모델용)는 손상된 사본을 삭제하고 다시 내려받습니다. 다른 것은 삭제되지 않습니다.
- **제거**는 확인 후 모델을 이 PC에서 지우며, 확보되는 공간을 알려 줍니다. 모델이 사용 중이면 호스트가 먼저 모델을 해제하고 다음에 무엇을 사용할지 묻습니다. 호스트가 다운로드한 파일만 삭제됩니다.

### 내 모델 추가하기

**내 모델 추가...**를 누르면 `.gguf` 파일을 선택할 수 있습니다. 호스트는 모델 폴더에 자체 사본을 만듭니다. 원본 파일은 변경되거나 이동되지 않습니다. 해당 행에는 **직접 추가**라고 표시되며, 호스트는 필요한 메모리를 추정할 수 없으므로 직접 실행해 보고 확인하세요. 이런 모델에서 **제거**를 누르면 호스트의 사본만 삭제됩니다.

### 공간 확보

**공간 확보**에는 앱이 직접 만든 잔여 파일이 나열됩니다. 이어 받을 수 없는 미완료 다운로드, 모델을 옮긴 뒤 남은 이전 사본, 검사에서 손상으로 확인된 모델 등입니다. 무엇이든 삭제하기 전에 확인을 받습니다. 사용 중인 모델과 직접 추가한 파일은 목록에 나타나지 않습니다. 이어 받을 수 있는 미완료 다운로드는 1주일 동안 보관됩니다.

### 모델 폴더와 모델 옮기기

**설정 > 모델 폴더**에서 새 다운로드를 저장할 위치를 정합니다. 기본 폴더를 쓰려면 비워 두고, `D:\Models`처럼 전체 경로를 입력한 뒤 Enter를 누르세요. 이미 다운로드된 모델은 이동하거나 삭제되지 않습니다. 원래 위치에 그대로 남고 목록에도 계속 표시됩니다. 옮기려면 **내 모델을 여기로 이동**을 선택하세요. 모델은 복사되고, 검사를 거친 뒤에야 이전 사본이 삭제됩니다. 이 작업 중에는 사용 중인 모델이 해제됩니다. **이동 취소**를 누르면 모든 것이 원래 자리에 남습니다.

### 메모리 예산과 막대

모델 페이지의 **메모리 예산** 막대는 RAM과 그래픽 메모리를 보여 줍니다. 불러온 모델이 사용하는 양, 모델을 불러오는 동안 예약된 양, 설정한 한도에 대해 남은 양을 확인할 수 있습니다(7절 참고). 메모리 한도를 넘는 불러오기는 아무것도 멈추기 전에 이유와 함께 거부됩니다.

[스크린샷: 모델 두 개가 로드된 상태의 메모리 예산 막대]

### 실행 위치: 그래픽 카드, 메모리, 프로세서만

모델이 어디에서 실행될지는 **설정 > 성능 > 실행 위치**(자동, 그래픽 카드, 프로세서)에서 정합니다. 그래픽 카드에 맞지 않는 모델은 일부가 프로세서에서 실행됩니다(느림). 모델별 배치(**프로세서만** 포함)는 11절을 참고하세요.

### 제한 사항과 무료/유료

- 목록의 모든 모델은 상업적 사용이 무료입니다(Apache 2.0 또는 MIT 라이선스). 각 모델은 자체 라이선스를 표시합니다.
- 모델은 발행자의 Hugging Face 페이지에서 다운로드됩니다. 호스트는 신뢰할 수 있는 서명된 모델 목록만 받아들입니다. 목록을 불러올 수 없으면 **모델 목록을 사용할 수 없음** 막대가 표시되지만, 이 PC에 이미 있는 모델은 계속 사용할 수 있습니다.

### 문제 해결

- *내려받을 모델 목록이 없음:* 인터넷 연결을 확인하고 홈에서 **다시 시도**를 누르세요.
- *다운로드가 멈춤:* **재개**를 누르세요. 여유 공간이 부족하면 공간을 확보하거나 폴더를 바꾸세요.
- *모델이 "너무 클 수 있음"으로 표시됨:* 더 작은 모델을 고르거나 설정 > 성능에서 부하를 낮추세요.

## 5. 앱과 권한

**기기와 앱**(Ctrl+3)을 엽니다.

- **응답 대기 중:** AI 사용을 요청한 앱이 여기와 알림 창으로 표시됩니다("이 PC에서 Voice Portal이 AI를 사용하도록 허용할까요?"). **허용**, **허용 안 함**, **나중에 결정** 중에서 선택하세요. 알림에는 앱이 검증된 Portal 앱인지, 설치된 앱이지만 Portal 앱이 아닌지, 아니면 검증되지 않았는지가 표시되며, 검증되지 않은 경우 어디에서 실행되었는지도 알려 줍니다. 직접 실행한 앱만 허용하세요.
- **AI 호스트를 사용할 수 있는 앱:** 허용된 앱마다 오늘의 요청 수와 마지막 사용 시점이 표시됩니다.
  - **일시 중지**를 누르면 다시 재개할 때까지 새 요청을 받지 않습니다. 앱의 접근 권한은 유지됩니다.
  - **우선순위**(높음, 보통, 낮음)는 여러 앱이 동시에 요청할 때 누가 먼저 처리될지 정합니다. 대화형 요청이 일괄 작업보다 먼저 처리됩니다. 오래 기다린 요청은 순서가 올라가므로 우선순위가 낮은 앱이 계속 밀려나지는 않습니다.
  - **접근 제거**를 누르면 다시 허용하기 전까지 앱이 중지됩니다. **실행 취소**가 잠시 나타납니다.

앱은 호스트를 사용하기 전에 반드시 요청해야 합니다. 다른 기기와의 공유를 켜지 않는 한(9절), 호스트는 이 PC에서만 연결을 받습니다.

[스크린샷: 응답 대기 중인 앱 한 개와 허용된 앱 한 개가 있는 기기와 앱 페이지]

개발자용: 호스트는 `http://127.0.0.1:41870`에서 OpenAI 호환 로컬 API(스트리밍 채팅 완성, 임베딩, 모델 목록)를 제공합니다. `api-v1.md`를 참고하세요.

**저장 위치:** 허용된 앱과 그 토큰은 호스트의 데이터 폴더에 저장되며, Windows 사용자 계정으로 보호됩니다. 앱의 접근 권한을 제거하면 해당 토큰도 제거됩니다.

## 7. 성능 설정

**설정 > 성능**은 AI 때문에 PC가 느려지는 것을 막아 줍니다. 변경 사항은 즉시 적용됩니다. 새 한도에 맞지 않는 모델은 다시 불러오거나 해제됩니다(디스크에는 남아 있습니다). **기본값으로 재설정**을 누르면 이 섹션이 복원됩니다.

| 설정 | 역할 | 기본값 |
|---|---|---|
| 성능 | 프리셋: **조용히**(속도는 약 절반, PC 반응성 유지), **균형**(좋은 속도, 다른 프로그램 우선), **빠르게**(가장 빠른 응답, 다른 프로그램이 느려질 수 있음), **사용자 지정** | 균형 |
| AI 최대 메모리 | AI가 이 값보다 많은 메모리를 사용하지 않음 | PC 메모리의 80% |
| 항상 비워 두기 | 다른 프로그램을 위해 비워 두는 메모리 | 프리셋으로 설정 |
| 실행 위치 | **자동**(도움이 될 때 그래픽 카드 사용), **그래픽 카드**(가장 빠름, 모델이 들어갈 때), **프로세서**(느리지만 그래픽 카드를 게임에 남겨 둠) | 자동 |
| AI용 그래픽 메모리 | AI가 사용할 수 있는 그래픽 메모리 상한 | 프리셋으로 설정 |
| 프로세서 코어 | 코어를 적게 쓰면 PC 반응성 유지 | 프리셋으로 설정 |
| 우선순위 | **낮음**(내 작업 우선) 또는 **보통** | 낮음 |
| 최대 프로세서 사용률 | 프로세서 사용의 상한 | 제한 없음(100%) |
| 다음 상황에서 속도 낮추기 | AI는 가장 낮은 우선순위로 실행되며, 프로세서의 최대 절반만 사용하고 끝나면 정상으로 돌아갑니다. 다음 중 선택할 수 있습니다: 게임이나 전체 화면 프로그램 실행 중, PC가 배터리 사용 중, 음성 받아쓰기처럼 실시간 작업을 하는 Portal 앱 | 전체 화면 프로그램, 배터리, 작업 중인 앱 모두 켜짐 |

**설정 > 일반**의 **유휴 시 메모리 해제**에서 **모델 계속 로드**, **5분 후**, **10분 후** 중 선택할 수 있습니다(기본값 10분, 배터리 사용 시 5분). 다음에 앱이 요청하면 모델이 다시 불러와집니다. 계속 로드해 두면 답변이 더 빠르지만 항상 메모리를 사용합니다.

슬라이더 힌트는 선택한 메모리로 모델이 그래픽 카드에 완전히 들어갈지, 일부만 프로세서에서 실행될지, 프로세서에서만 실행될지 알려 주며, 현재 모델이 더 이상 맞지 않으면 더 작은 모델을 제안합니다.

[스크린샷: 설정 > 성능]

**문제 해결:** 그래픽 카드가 있는 PC에서 답변이 느리다면, 보통 모델의 일부만 그래픽 카드에 들어가기 때문입니다. 더 작은 모델을 고르거나 AI용 그래픽 메모리를 늘리세요. 사용 중 PC가 버벅거린다면 **조용히**를 고르거나 최대 프로세서 사용률을 낮추세요.

각각 따로 끌 수 있습니다. 같은 페이지의 **기본값으로 재설정**으로 복원할 수 있습니다.

## 9. 다른 기기가 이 PC를 사용하게 하기

**설정 > 다른 기기**입니다. 기본값은 꺼짐입니다. 켜면, 홈 네트워크에 있는 내 노트북이나 다른 PC가 이 PC의 AI를 사용하도록 요청할 수 있습니다. 기기는 먼저 코드로 페어링해야 하며, 그 기기의 각 앱은 여전히 내 승인이 필요합니다.

### 기기 페어링

1. **다른 기기가 이 PC의 AI를 사용하도록 허용**을 켭니다. Windows가 네트워크 규칙을 허용할지 물을 수 있습니다.
2. **기기 페어링**을 누릅니다. 코드와 QR 코드가 나타나며, **링크 복사**를 누르면 페어링 링크가 복사됩니다.
3. 다른 기기에서 Portal 앱(또는 클라이언트 모드의 Portal AI Host, 12절)을 열고 PC에 연결하도록 선택한 다음, 코드를 스캔하거나 입력하거나 링크를 붙여 넣습니다.
4. 기기는 무언가를 보내기 전에 이 PC와 통신하고 있는지 확인한 뒤, PC 이름과 지문을 보여 주며 확인을 요청합니다.

코드는 한 번만 사용할 수 있으며, 5분 동안, 한 기기에서만 유효합니다. 잘못된 입력을 여러 번 하면 코드가 소진됩니다. 새 코드가 필요하면 **기기 페어링**을 다시 누르세요. **페어링 취소**로 중단할 수 있습니다.

[스크린샷: 페어링 코드와 QR 코드]

### 페어링된 기기

페어링된 기기마다 마지막 사용 시각과 **제거** 버튼이 표시됩니다. 기기를 제거하면 그 기기의 접근이 즉시 중단되고, 처리 중이던 요청도 끝납니다. 다시 사용하려면 기기를 다시 페어링해야 합니다. 최대 **16**대까지 페어링할 수 있습니다.

### 이 카드의 다른 설정

- **외출 중에도 이 PC에 연결**(릴레이). 13절을 참고하세요. 기본값: 다른 기기를 켜면 함께 켜짐.
- **릴레이 액세스 키**. 13절 참고. 기본값: 꺼짐.
- **기기가 모델을 교체할 수 있음**. 11절을 참고하세요. 기본값: 꺼짐.

**네트워크로 전달되는 내용:** 요청과 답변은 내 기기들 사이에서 암호화되어 전달됩니다. 홈 네트워크 연결은 페어링할 때 기기가 고정(pin)해 둔 인증서를 사용합니다. 선택 사항인 블라인드 릴레이(13절)를 제외하면, 당사 서버로 전송되는 것은 없습니다.

**문제 해결:** *기기가 이 PC를 찾지 못함:* 두 기기가 같은 네트워크에 있는지, 이 PC가 켜져 있고 호스트가 실행 중인지 확인하세요. *코드가 "맞지 않음" 또는 "소진됨":* 새 코드를 만드세요. *"홈 네트워크에 없음":* 먼저 집에서 한 번 페어링하세요.

## 10. 이 PC의 기기

**이 PC의 기기** 페이지에는 페어링된 노트북마다 카드가 하나씩 표시됩니다. 각 노트북이 무엇을 하고 있는지 보고 사용을 제한하는 곳입니다.

[스크린샷: 기기 카드 두 개가 있는 이 PC의 기기 화면]

### 카드에 표시되는 내용

- 상태(온라인, 유휴, 오프라인), 경로(홈 네트워크 또는 릴레이(외출 중)), 마지막 접속 시각.
- 지금 실행 중인 작업과 대기 중인 작업.
- 오늘의 요청 수와 토큰 수, 앱별 7일 막대.
- 사용 중인 모델, 그 모델을 불러온 주체, 초당 토큰 수와 첫 바이트까지 걸린 시간.

### 제어 항목

| 제어 | 역할 |
|---|---|
| 일시 중지 / 재개 | 기기 전체 또는 그중 한 앱을 일시 중지합니다. 노트북은 "일시 중지됨"이라는 명확한 응답을 받으며, 대체 수단을 설정해 두었다면 그것을 사용합니다. |
| 이름 바꾸기 | 기기에 표시되는 이름을 바꿉니다 |
| 제한 | 우선순위, 일일 한도, 조용한 시간, 허용 모델 (아래 참고) |
| 모델 제어(스위치) | 이 기기가 모델을 불러오고 해제할 수 있게 합니다. 11절 참고 |
| 되찾기 | 이 기기가 불러온 모델을 해제합니다. 이 PC 자체의 선택이 돌아옵니다. 모델 파일은 건드리지 않습니다. |
| 잊기 | 기기를 제거합니다. 접근이 즉시 중단되고 사용 기록도 삭제됩니다. 모델은 건드리지 않습니다. |

**제한**(카드의 **제한** 버튼을 누른 뒤 **저장**):

- **이 PC의 앱과 같은 우선순위.** 끔(기본값): 이 PC의 앱이 먼저 처리됩니다. 켬: 기기도 같은 줄에서 기다립니다.
- **하루 요청 수**와 **하루 토큰 수.** 기본값: 제한 없음. 한도에 도달하면 기기에는 이 PC 시간 기준 자정 이후에 다시 시도하라는 안내가 전달됩니다.
- **조용한 시간**, **시작**과 **종료**(이 PC 시간 기준). 이 시간대에는 기기에 응답하지 않습니다. 기본값: 꺼짐.
- **이 기기가 사용할 수 있는 모델.** 기본값: 모든 모델.

### 게임 모드

페이지 맨 위에 있습니다. **기본값: 꺼짐.** 켜면, 다른 기기의 호출에 대해 게임을 하는 동안 이 PC가 바쁘다고 응답하여, 게임이 그래픽 카드를 계속 쓸 수 있습니다. Windows가 전체 화면 게임을 감지하거나, 다른 프로그램이 약 10초 동안 그래픽 카드의 3D 엔진을 40% 이상 사용 중일 때 이 PC는 "게임 중"으로 간주됩니다. 창 모드나 테두리 없는 창 게임도 포함됩니다. 부하가 끝난 뒤 약 30초 후에 집계가 멈춥니다. PC에서 그래픽 카운터를 사용할 수 없으면 전체 화면 감지만 사용됩니다. 이 경우 노트북은 자체 설정에 따라 대체 수단을 사용합니다.

### 알림

새 기기가 페어링되거나, 기기가 외출 중에 릴레이를 통해 연결되면 Windows 알림이 나타납니다. 끄려면 **설정 > 알림 > 기기가 페어링되거나 외부에서 연결될 때**를 사용하세요.

### 데이터

사용량 수치는 횟수만 기록합니다(앱별, 날짜별 요청 수와 토큰 수. 7일간 보관). 프롬프트나 답변 내용은 저장되지 않습니다. **잊기**는 해당 기기의 사용량 파일만 삭제합니다.

## 11. 모델 제어와 두 개의 모델 동시 실행

기본적으로 페어링된 노트북은 이 PC에 현재 불러와진 모델을 그대로 사용합니다. 기기에 더 많은 권한을 줄 수도 있습니다.

### 모델 제어

**설정 > 다른 기기**에서 해당 기기의 행에 있는 **모델 제어**(기본값: 꺼짐)를 켭니다. 켜면 노트북은 다음을 할 수 있습니다:
- 이 PC에 설치된 모델을 불러오고 해제.
- 모델이 실행될 위치 선택(자동, 그래픽 카드, 시스템 메모리, 프로세서만).
- 이 PC의 모델 중 자신의 앱이 사용할 모델 선택.

권한을 주었는지와 관계없이, 기기는 모델을 다운로드, 제거, 확인, 가져오기를 할 수 없고, 설정을 바꾸거나 파일에 접근할 수도 없습니다. 끄면 기기의 다음 호출은 거부됩니다. 기기를 제거하면 권한도 함께 제거되며, 다시 페어링해도 권한은 복구되지 않습니다.

이 PC에는 누가 무엇을 불러왔는지 표시됩니다: "<기기>가 불러옴: <모델> (그래픽 카드)". **되찾기**(카드와 설정 모두에 있음)를 누르면 기기가 불러온 모델이 해제됩니다. 이 PC 자체의 선택이 돌아와서 다음 요청 때 불러와집니다.

### 두 개의 모델 동시 실행

모델 제어를 켜면, 노트북은 이 PC에서 두 번째 모델을 계속 불러와 둘 수 있습니다. 예를 들어 하나는 그래픽 카드에서, 다른 하나는 시스템 메모리에서 실행하는 식입니다.
- 내 모델은 첫 번째 슬롯에 머뭅니다. 기기의 모델은 두 번째 슬롯에 들어가므로, 기기가 자기 모델을 쓰려고 내 모델을 밀어내는 일은 없습니다.
- 슬롯마다 독립된 대기열이 있어서 두 모델이 동시에 답변할 수 있습니다. 두 번째 모델을 지정한 요청은 그쪽으로 가고, 그 밖의 요청은 내 모델로 갑니다.
- 불러오기 전에 호스트는 다른 슬롯이 이미 쓰고 있는 양을 내 한도에 더해 계산합니다. 들어가지 않는 두 번째 모델은 "메모리 부족"으로 거부됩니다. 아무것도 몰래 멈추지 않습니다.
- 내 선택이 항상 우선합니다. 다른 모델을 고르거나, 무언가를 해제하거나, 내 모델이 메모리를 필요로 하면, 기기의 모델은 중지되고 기기에 그 사실이 전달됩니다.
- 기기의 두 번째 모델은 영원히 로드된 상태로 두지 않습니다. 다른 모델과 마찬가지로 유휴 상태가 되면 해제됩니다.
- **프로세서만**은 그래픽 관련 계층을 쓰지 않고 프로세서의 약 절반을 사용해 모델을 실행합니다. 예를 들어 다른 모델이 그래픽 카드를 쓰는 동안 프로세서에서 보조 모델을 돌리는 경우에 씁니다.

[스크린샷: 서로 다른 소유자가 불러온 두 모델이 있는 모델 페이지]

### 기기가 모델을 교체할 수 있음

**설정 > 다른 기기 > 기기가 모델을 교체할 수 있음**(기본값: 꺼짐). 꺼져 있으면 기기는 내 앱이 사용 중인 모델을 해제할 수 없습니다. 켜져 있으면 해제할 수 있으며, 내 앱은 다음 요청 때 모델을 다시 불러옵니다. 기기가 두 대라면 먼저 불러온 기기가 모델을 유지합니다.

## 12. 노트북에서 집 PC 사용하기 (클라이언트 모드)

클라이언트 모드는 노트북의 Portal AI Host가 직접 모델을 실행하는 대신, 내 다른 PC의 AI를 사용하도록 합니다. 노트북의 앱은 평소처럼 동작합니다.

### 설정

1. 집 PC에서 **다른 기기가 이 PC의 AI를 사용하도록 허용**을 켜고 **기기 페어링**을 누릅니다(9절 참고). **링크 복사**를 누르고 링크를 노트북에 보냅니다.
2. 노트북에서 **설정 > 집 PC**를 엽니다(또는 환영 창에서 **내 집 PC 사용**을 선택).
3. **AI 실행 위치**에서 **내 집 PC 사용**을 고릅니다. **내 집 PC 사용** 창이 열립니다. **링크 붙여넣기**로 링크를 붙여 넣고, **다음**을 누른 뒤 PC 이름과 지문을 확인하고 **페어링**을 누르세요. 노트북 이름을 정합니다.
4. 홈에 PC 이름과 상태가 표시됩니다: **연결됨 - 홈 네트워크**, **연결됨 - 릴레이 경유**, **연결 중...** 또는 **연결할 수 없음**.

[스크린샷: 노트북의 페어링 창]

### 설정 (설정 > 집 PC)

| 설정 | 선택지 | 기본값 |
|---|---|---|
| AI 실행 위치 | 이 PC / 내 집 PC 사용 | 이 PC |
| 집 PC에 연결할 수 없을 때 | **없음**(앱은 각자 내장된 AI 사용) / **이 노트북의 모델 사용**(필요할 때 불러옴) | 없음 |
| 외출 중 연결 방식 | **자동** / **수동**(이 경우 **릴레이 사용** 스위치는 현재 세션에만 적용되며, 앱을 닫으면 초기화) | 자동 |

- 집 PC에 처음 연결할 수 없을 때, 어떻게 할지 한 번 묻습니다. 여기서 언제든 바꿀 수 있습니다.
- **PC 다시 페어링**은 다시 페어링합니다. **페어링 해제**는 PC를 잊어버립니다(모델과 다운로드는 그대로 유지). **PC 변경**(홈에 있음)은 이 설정을 엽니다. **이 PC에서 AI 실행**(홈에 있음)은 클라이언트 모드를 끝내지만 저장된 페어링은 유지합니다.
- 집 PC가 모델 제어 권한을 부여하면 **<PC 이름>의 모델**이 나타나고, 불러오기, 해제, 배치 버튼과 **앱별 PC 모델**이 표시됩니다. 권한이 없으면 "<PC 이름>의 소유자에게 이 노트북의 모델 제어를 켜 달라고 요청하세요"라고 표시됩니다.
- 클라이언트 모드의 노트북은 다른 기기의 연결을 받지 않으며, 집 PC로 가는 중계 지점이 될 수도 없습니다.

### 이 노트북의 모델은 어떻게 되나요

클라이언트 모드에 들어가면 노트북에 불러와 있던 모델이 메모리 확보를 위해 해제됩니다. 모델 파일, 다운로드, 모델 폴더는 건드리지 않습니다. 클라이언트 모드를 끝내면 다음 요청 때 모델이 다시 불러와집니다.

### 문제 해결

- **연결할 수 없음:** 집 PC가 켜져 있고 같은 네트워크에 있는지 확인하거나 릴레이를 켜세요.
- **"이 노트북은 PC에서 제거되었습니다":** 집 PC가 노트북을 제거했습니다. **다시 페어링**을 선택하세요.
- **"<PC>의 신원이 변경되었습니다":** PC의 인증서가 노트북에 저장된 것과 더 이상 일치하지 않습니다. 예상하지 못한 일이라면 다시 페어링하지 마세요. 짐작되는 이유가 있다면 페어링을 해제한 뒤 다시 페어링하세요.
- **외출 중 페어링 실패:** 먼저 집에서 한 번 페어링하세요. 페어링 링크는 집 네트워크의 주소를 가리켜야 합니다.
- **일시 중지, 조용한 시간, 게임 중, 또는 일일 한도 소진:** PC가 노트북에 이유를 알려 주며, 노트북은 대체 수단을 사용합니다.

**저장 위치:** 노트북은 페어링 정보를 호스트의 데이터 폴더 아래 `client\`에 보관합니다. 기기 키와 토큰은 Windows 사용자 계정으로 보호됩니다. **페어링 해제**를 누르면 이것들이 삭제됩니다. 이 폴더의 백업은 다른 Windows 사용자 계정에서는 복원할 수 없습니다.

## 13. 외출 중: 릴레이와 릴레이 액세스 키

릴레이를 사용하면 페어링된 기기가 어디에서든 내 PC에 접근할 수 있습니다. **설정 > 다른 기기 > 외출 중에도 이 PC에 연결**에서 설정합니다.

- 내 PC는 작은 릴레이 서비스에 외부로 연결합니다. 릴레이는 읽을 수 없는 암호화된 데이터만 전달하며, 내용은 아무것도 저장하지 않습니다. 각 기기는 여전히 페어링되어 있어야 하며, 모든 요청에 서명합니다.
- 상태 줄에는 **외출 중에도 접속 가능**, **홈 네트워크만**, **릴레이에 연결 중...** 또는 **릴레이에 연결할 수 없음** 중 하나가 표시됩니다.
- 일반적인 웹 포트를 사용하므로 대부분의 회사 네트워크에서도 허용됩니다.
- **회사 기기:** 업무 내용이 개인 PC로 전달됩니다. 먼저 회사 규정을 확인하세요.

### 릴레이 액세스 키

**설정 > 다른 기기 > 릴레이 액세스 키**(기본값: 꺼짐). 켜면 페어링 코드에 들어 있는 키로 페어링된 기기만 릴레이를 통해 이 PC에 접근할 수 있습니다. 낯선 사람이 내 PC의 릴레이 슬롯을 모두 써 버리는 것을 막아 줍니다.

- **페어링하기 전에** 켜세요. 이전에 페어링한 기기는 릴레이를 사용하려면 다시 페어링해야 합니다(홈 네트워크는 계속 작동합니다).
- **새 키**를 누르면 확인 후 새 키가 만들어집니다. 페어링된 모든 기기는 릴레이를 사용하려면 다시 페어링해야 합니다. 집에서는 아무것도 바뀌지 않습니다. 기기를 제거해도 키는 바뀌지 않으므로, 신뢰하지 않는 기기를 제거했다면 **새 키**를 사용하세요.
- 키 파일을 사용할 수 없으면 릴레이는 열리지 않고 꺼진 상태로 남으며, 홈 네트워크는 계속 작동합니다. 손상된 키 파일은 `.bad` 이름으로 옆에 보관되며 절대 덮어쓰지 않습니다.
- 스위치가 켜진 상태를 유지하지 못하면 릴레이 서비스 쪽 업데이트가 필요할 수 있습니다. 그럴 때는 스위치를 다시 끄세요.

**제한:** 릴레이는 한 기기가 보낼 수 있는 속도와 양을 제한하여, 한 기기가 서비스를 넘치게 하지 못하도록 합니다. 일반적인 사용은 이 한도보다 훨씬 낮습니다.

## 14. 개인정보와 충돌 보고서

- **분석이나 사용 추적은 없습니다.** 충돌 보고서만 PC 밖으로 나갈 수 있으며, 그것도 켜 두었을 때만입니다.
- **텍스트는 내 기기 안에만 머뭅니다.** 호스트는 프롬프트와 답변을 저장하거나 기록하지 않습니다. 로그에는 횟수, 시간, 상태만 남습니다.
- **충돌 보고서는 기본적으로 켜져 있으며, 끌 수 있습니다.** 창이나 백그라운드 호스트가 충돌하면, 짧은 보고서가 문제 수정에 도움이 됩니다. **설정 > 개인정보 > 충돌 보고서 보내기**에서 언제든 끌 수 있으며, 즉시 적용됩니다. 환영 창에도 같은 선택지가 있으며, 보내기 전에 기본적으로 선택되어 있습니다.
  - **보내지는 것:** 오류 종류와 발생 위치(함수 이름과 모듈 이름), 앱과 Windows 버전, Store 빌드 여부, 창에서 발생했는지 호스트에서 발생했는지.
  - **보내지지 않는 것:** 프롬프트나 답변, 입력한 모든 내용, 파일 이름이나 폴더 경로, 컴퓨터 이름이나 사용자 이름, 어떤 앱이 호스트를 사용하는지, IP 주소. 오류 메시지 텍스트도 제거됩니다.
  - **90일 보관** 후 삭제됩니다.
  - **보내지는 내용**(설정 > 개인정보)을 누르면 개인정보 페이지가 열립니다.
- **모두 암호화됩니다.** 이 PC에서 내 다른 기기로 나갈 때는 항상 암호화됩니다.
- **개인정보 처리방침:** 정보 > **개인정보 처리방침**.
- 질문이나 보고서 삭제 요청: mindthaapp@gmail.com

[스크린샷: 충돌 보고서 스위치가 있는 설정 > 개인정보]

## 15. 데이터 저장 위치, 백업, 삭제

모든 것은 앱 자체의 데이터 폴더 안에 있습니다. **정보 > 데이터 폴더 열기**로 열 수 있습니다.

| 내용 | 위치(데이터 폴더 안) | 백업 여부 |
|---|---|---|
| 다운로드한 모델 | `models\`, 또는 설정에서 고른 폴더의 `Portal AI Host Models\` | 선택 사항. 다시 다운로드할 수 있습니다. 용량이 큽니다. |
| 설정 | `settings.json` | 예 |
| 허용된 앱과 그 토큰 | 호스트의 앱 저장소 | 이동 불가(Windows 사용자 계정으로 보호) |
| 페어링된 기기, 제한, 사용 통계 | 호스트의 기기 저장소와 기기별 작은 통계 파일 | 이동 불가 |
| 노트북 페어링(클라이언트 모드) | `client\` | 이동 불가. 새 PC에서는 다시 페어링하세요. |
| 로그 | `logs\`(순환 저장, 최대 10MB) | 아니요 |
| 앱용 검색 파일 | `discovery\host.json` | 아니요 |

**백업:** Portal AI Host를 닫고 데이터 폴더를 복사하세요. 설정과 모델은 다시 복사해 넣어 복원할 수 있습니다. 앱 권한, 기기 페어링, 토큰은 Windows 사용자 계정과 이 PC에 맞춰 보호되므로, 새 PC에서는 앱을 다시 허용하고 기기를 다시 페어링해야 합니다.

**삭제:**
- *모델 하나:* **모델 > 제거**. 호스트가 다운로드한 파일만 삭제됩니다.
- *잔여 파일:* **모델 > 공간 확보**.
- *기기:* **잊기**(이 PC의 기기) 또는 **제거**(설정).
- *앱 접근 권한:* **접근 제거**(기기와 앱).
- *전부:* 앱을 제거하세요. 직접 선택한 사용자 지정 모델 폴더는 그대로 남으며, 완전히 지우려면 그 안의 `Portal AI Host Models` 폴더를 직접 삭제하세요.

이 앱은 자신이 만들지 않은 것은 절대 삭제하지 않으며, 파일을 덮어쓰지 않습니다. 직접 추가한 모델은 호스트의 사본으로만 제거되며, 원본 파일은 건드리지 않습니다.

## 17. 문제 해결과 FAQ

**호스트가 실행 중이 아니라고 나옵니다.** 홈에서 **Portal AI Host 시작**을 누르세요. 시작할 수 없으면 PC를 다시 시작하세요. 그래도 실패하면 Store에서 다시 설치하세요.

**"이 PC의 다른 Windows 사용자가 Portal AI Host를 이미 실행 중입니다."** 그 사용자에게 앱을 종료해 달라고 요청하거나, 그 사용자로 로그인하세요.

**답변이 느립니다.** 7절을 참고하세요. 그래픽 메모리에 비해 너무 큰 모델은 일부가 프로세서에서 실행됩니다.

**앱이 사용할 수 있는 AI가 없다고 합니다.** 앱이 허용되어 있는지(기기와 앱), 일시 중지되지 않았는지, 모델이 설치되어 있고 PC에 비해 너무 크지 않은지 확인하세요.

**첫 답변은 느리고, 이후 답변은 빠릅니다.** 모델이 휴면 상태였습니다. 첫 요청 때 불러와집니다. 이를 피하려면 설정 > 일반에서 **모델 계속 로드**를 선택하세요.

**내 데이터가 어딘가로 전송되나요?** 아니요. 프롬프트와 답변은 내 기기에만 머뭅니다. 충돌 보고서만 나갈 수 있으며(14절), 이것도 끌 수 있습니다.

**인터넷 없이 쓸 수 있나요?** 네. 모델을 한 번 내려받은 뒤에는 가능합니다.

**비용이 드나요?** 아니요.

**어떤 모델을 골라야 하나요?** 추천 모델을 고르세요. PC가 느리게 느껴지면 더 작은 모델을, 더 나은 답변을 원하고 메모리가 충분하다면 더 큰 모델을 고르세요.

**다운로드가 "다운로드 확인 중"에서 멈췄어요.** 기다리세요. 큰 파일은 확인하는 데 1분쯤 걸립니다.

**페어링 시 "기기가 너무 많습니다"라고 나옵니다.** 한도는 16대입니다. 한 대를 제거하세요.

**트레이 아이콘은 어디 있나요?** 시계 근처의 화살표를 클릭하면 숨겨진 아이콘이 보입니다.

그래도 해결되지 않으면 **정보 > 버전 복사**를 사용한 뒤 mindthaapp@gmail.com으로 메일을 보내고, 메시지에 버전을 붙여 넣으세요.

## 18. 추후 제공 예정

다음은 계획된 기능으로, 현재 앱에는 포함되어 있지 않습니다.

- **모델 페이지의 카테고리:** 작업별(채팅과 글쓰기, 코딩, 추론, 비전, 임베딩, 음성)로 묶고 필터와 검색을 제공합니다.
- **이 PC에서 이미지와 동영상 생성.** 여러 장면을 이어 동영상으로 만드는 "디렉터" 기능을 포함합니다. 엔진이 만들어질 때까지 동영상 모델은 "곧 제공"으로 표시됩니다.
- **AI Portal에서 답변할 모델 선택**, 그리고 모델끼리 도움을 요청하는 기능.
- **macOS 버전.**
